# AI Context Pack

> Share anything. Clean it, compress it, redact it, and send it to any AI.

AI Context Pack 是一款面向 iPhone/iPad 的本地优先工具：把散落在不同 App 中的截图、图片、PDF、网页链接和文字，整理成一份结构清晰、大小可控、敏感信息经过确认的“上下文包”，再通过系统分享菜单发送给 ChatGPT、Claude、Codex、邮件、Slack、GitHub 或其他目标。

## 1. 要解决的问题

用户在向 AI 提供上下文时，通常需要反复执行：寻找资料、逐张上传、复制文字、解释顺序、压缩图片、删除重复内容、隐藏密码或个人信息。这个过程比真正提出问题更耗时，而且经常出现以下问题：

- 一次只能分享一个来源，资料顺序混乱。
- 截图包含状态栏、导航栏和重复区域，浪费 token 与上传时间。
- PDF 可能是扫描件，AI 无法稳定读取。
- 图片、文本和链接需要手工拼接成 prompt。
- 截图可能暴露 API Key、邮箱、手机号、地址或账号信息。
- 不同 AI 对文件数量、文件大小和上下文长度有不同限制。

AI Context Pack 不做新的聊天机器人，而是把“准备 AI 上下文”变成一个可复用的系统级动作。

## 2. 目标用户

### 首发用户

- 程序员：整理报错截图、日志、代码片段、需求与复现步骤。
- 产品经理和设计师：整理竞品截图、用户反馈、原型与说明。
- 客服和运营：组合工单、聊天截图、订单信息并隐藏隐私数据。
- AI 重度用户：频繁在 ChatGPT、Claude、Codex 等工具之间传递上下文。

### 后续用户

- 研究人员和学生：整理网页、论文、批注和引用。
- 内容创作者：将素材与参考资料整理为生成任务输入。
- 法务、财务等专业用户：在本地完成资料脱敏和打包。

## 3. 核心设计原则

1. **Local first**：MVP 的 OCR、去重、压缩、敏感信息检测和打包默认在设备上完成。
2. **User in control**：删除、遮挡和内容改写必须可预览、可撤销；高风险操作不静默执行。
3. **No new habit**：主要入口是 iOS Share Extension，也支持在主 App 内导入。
4. **Output over storage**：产品价值是生成可立即使用的输出，不是长期收藏或截图分类。
5. **Deterministic first**：MVP 优先使用可测试的 OCR、规则和本地框架，不依赖云端 LLM。
6. **Destination-neutral**：输出使用 Markdown、PDF 和标准文件，不绑定单一 AI 平台。

## 4. MVP 范围

### 支持输入

- 一张或多张图片：PNG、JPEG、HEIC。
- PDF：文本型 PDF 与扫描型 PDF。
- 纯文本或选中的文字。
- 网页链接：保存 URL、标题和从 Safari 分享得到的可用文本；MVP 不做服务端网页爬取。
- 从 Photos、Files、Safari 或其他支持系统分享菜单的 App 导入。

### 暂不进入 MVP

- 屏幕录制和视频帧抽取。
- 登录、账号系统和团队协作。
- iCloud 同步。
- 云端 LLM 总结、问答或 Agent。
- ChatGPT、Claude 等第三方账号授权和直接 API 调用。
- 浏览器扩展、macOS 和 MCP Server。

## 5. 使用方式

### 路径 A：从其他 App 分享

1. 用户在 Photos、Files、Safari 或其他 App 中选择内容。
2. 点击系统 Share，选择 **Context Pack**。
3. Share Extension 将内容复制到 App Group 的临时 Inbox，并显示接收结果。
4. 用户打开主 App，进入新建的 Draft Pack。
5. App 自动执行解析、OCR、基础清洗、去重和大小估算。
6. 用户调整顺序、删除内容、编辑标题与说明。
7. App 标记可能的敏感信息，用户逐项确认保留或遮挡。
8. 用户选择输出预设并预览最终结果。
9. 通过系统 Share Sheet 发送到任意 AI 或保存到 Files。

### 路径 B：在主 App 中创建

1. 点击 New Pack。
2. 从 Photos、Files、剪贴板或文本输入中添加内容。
3. 选择目标预设，例如 “Balanced Markdown” 或 “Compact Attachments”。
4. 完成处理、检查和导出。

### 路径 C：快速模式

1. 用户分享内容到 Context Pack。
2. 若所有处理都满足安全条件，Extension 显示 Quick Export。
3. 用户确认后直接分享标准 Markdown 或压缩附件。
4. 检测到敏感信息、OCR 失败或超出预算时，必须进入主 App 复核。

## 6. 主要功能

### 6.1 Pack 工作区

- 每个 Pack 具有标题、可选说明、内容项列表、输出预设和处理状态。
- 内容项支持拖拽排序、批量选择、删除、重试、查看原始内容与处理结果。
- 所有自动变更都保留原始文件，用户可恢复。
- Pack 支持 Draft、Ready、Exported、Failed 等明确状态。

### 6.2 内容提取

- 图片使用 Apple Vision 做 OCR，记录文本块、置信度和坐标。
- 文本型 PDF 直接提取文字；扫描页回退到逐页 OCR。
- 文本输入保持原始格式，并规范换行、不可见字符和编码。
- URL 项保留原始链接与可用标题；从分享上下文中接收正文时一并保存。

### 6.3 清洗与去重

- 通过内容哈希识别完全重复的文件。
- 通过感知哈希提示近似重复的图片。
- 规范 OCR 文本中的空白、重复换行和明显乱码。
- 对相邻截图的重叠内容给出提示；MVP 不自动拼接或裁掉未经用户确认的区域。
- 清洗规则必须可解释，并显示节省的字符数或文件大小。

### 6.4 预算优化

- 显示原始大小、处理后大小、图片数量、PDF 页数、字符数和估算 token 数。
- 提供 Quality、Balanced、Compact 三种预设。
- 图片根据预算调整尺寸和压缩质量，保留可读性下限。
- 超出预算时给出明确建议：降低图片质量、只保留 OCR 文本、拆分 Pack 或删除内容。
- token 只作为估算值显示，避免宣称与任意模型的真实计费完全一致。

### 6.5 敏感信息检测与遮挡

- 检测常见 API Key、JWT、Authorization Header、私钥片段、邮箱、手机号、IP、URL 凭据和银行卡样式数字。
- 图片中的命中项映射回 OCR 坐标，在预览中高亮。
- 用户可以按项、按类别或手工框选遮挡。
- 导出图片必须真正生成新像素，不只覆盖可移除的 UI 图层。
- 默认不修改原始文件，不把原始敏感内容写入日志或分析事件。

### 6.6 编辑与预览

- Pack 级别：标题、目标问题、说明、输出格式、预算预设。
- Item 级别：标题、顺序、包含模式（原图、OCR 文本、两者）、裁剪和遮挡。
- 最终预览必须与导出结果一致。
- 处理失败的内容不会被静默忽略，导出前显示完整性警告。

### 6.7 输出

- **Markdown**：包含 Pack 标题、用户说明、目录、每个 Item 的来源、正文和附件引用。
- **PDF**：生成便于阅读和存档的合并文档。
- **Attachment bundle**：输出 Markdown 加处理后的附件，可选择 ZIP 或多文件分享。
- **Clipboard**：复制纯文本或 Markdown。
- **System Share**：发送到任何已安装的目标 App。

## 7. 示例

### 示例：请 AI 修复移动端 Bug

输入：一段屏幕截图、两张报错截图、一份需求 PDF、复制的控制台日志。

处理：去除重复截图、OCR 错误信息、标记 Token、压缩图片，并按“复现过程 → 错误 → 需求 → 日志”排序。

输出：一份 Markdown 上下文说明和经过遮挡的附件包，可直接分享给 ChatGPT、Claude 或 Codex。

### 示例：整理产品调研

输入：多个竞品页面截图、网页链接和用户评论。

处理：提取文字、识别重复截图、统一来源信息并控制文件大小。

输出：结构化 Markdown，可作为后续比较分析的输入。

## 8. 隐私与数据边界

- MVP 不要求账号，不默认上传用户内容。
- 二进制原件保存在 App 私有目录；元数据存储在本地数据库。
- Share Extension 的临时文件在成功导入或到期后清理。
- 导出前展示将要共享的具体文件和可能仍存在的风险。
- 崩溃与性能诊断不得包含用户原文、OCR 结果、文件名、URL 查询参数或敏感检测结果。
- 若未来加入云端能力，必须逐项 opt-in，并在上传前展示内容、提供方和目的。

## 9. MVP 成功标准

- 首次用户可在 60 秒内完成“分享内容 → 生成 Pack → 导出”。
- 典型 10 张截图的处理在支持设备上 15 秒内完成，且 UI 保持可响应。
- 100% 的导出都能追溯到明确的输入项；失败项不会被静默遗漏。
- 关闭网络后，图片、PDF、文本的核心流程仍可完成。
- 测试语料中的已支持敏感模式达到预设召回率，且所有遮挡导出通过像素级验证。
- Beta 阶段至少完成 20 个真实任务，任务成功率达到 80% 以上。
